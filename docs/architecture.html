Factory Inventory Management: Architecture

A Vue 3 single-page app talks to a read-only FastAPI service, which serves JSON fixture data held in memory. There is no database and no authentication. This page shows how the pieces connect and what happens when a filter changes, and lists the gaps found in the code.

System architecture

Two dev processes: Vite on port 3000 serves the client, and uvicorn on port 8001 runs the API. The browser calls the API directly rather than through a proxy.

Data flow: changing a filter

Filter state lives in one place, useFilters.js. Its refs are defined at module level, so every component that calls useFilters() shares the same four values. Each view watches the ones it cares about and re-fetches when they change.

How the server filters

apply_filters: warehouse is an exact, case-sensitive match. Category and status are case-insensitive, which is why FilterBar can send lowercase values.

filter_by_month: a substring match of 2025-MM against order_date. It also accepts quarters (Q1-2025 and so on), but the UI never sends them.

Where state lives

Raw data: refs in each view (allOrders, inventoryItems, …).

Derived data: computed properties for charts, KPIs and tables.

Shared: filters (useFilters), locale and currency (useI18n, saved in localStorage), and a mock user (useAuth).

Gaps and things to know

Found while reading the code. Some may be deliberate exercises for the workshop.

  1. Task endpoints are missing. On every page load, App.vue sends GET /api/tasks and gets a 404, which shows in the browser console. Creating, toggling and deleting a task call POST, PATCH and DELETE on the same path, and the server has no route for any of them.
  2. The purchase-order flow is half-built. Dashboard.vue uses <PurchaseOrderModal>, but there is no component file, so Vue logs "Failed to resolve component". api.js has the client calls and main.py has the Pydantic models, but there are no routes.
  3. Backlog.vue is orphaned. The view exists but is not registered in the router, so no URL reaches it.
  4. Four of the five Overview KPIs are hard-coded. Turnover 4.2 (Dashboard.vue:18), orders fulfilled 187 of 200 and fill rate 96.8% (Dashboard.vue:340–341), and processing time 2.8 days (Dashboard.vue:62) never change with the filters. Only Revenue YTD uses API data.
  5. Filters don't apply to everything. CLAUDE.md says the four filters apply to all data, but demand, backlog, spending and reports accept no filters, and the summary's total_backlog_items ignores them. Inventory has no time dimension, so Time Period and Status don't affect it.
  6. The API address is hard-coded. api.js and Reports.vue both contain http://localhost:8001, with no environment config or Vite proxy. The server allows every CORS origin and binds to 0.0.0.0, so it is reachable from your local network. That's fine for development but not suitable for deployment.
  7. The API is read-only and in memory. There are no write routes. uvicorn runs without reload, so after changing main.py or the JSON files you have to restart the backend. Vite hot-reloads the frontend.
  8. Tests cover only the backend. tests/backend uses pytest and TestClient. There are no frontend tests.

Running it

Backend: localhost:8001

cd server
uv sync
uv run python main.py

Frontend: localhost:3000

cd client
npm install
npm run dev

To start both at once, run ./scripts/start.sh; to stop them, run ./scripts/stop.sh. To run the backend tests (40 pass at this commit): cd tests && uv run --project ../server pytest backend/ -v. The shorter uv run pytest given in tests/README.md and server/CLAUDE.md fails, because tests/ has no pyproject.toml of its own.
